# kafka-admin

Маленький reconciler: читает `topics.yaml` и приводит топики Kafka к описанному состоянию
через AdminClient API (confluent-kafka). Работает на живой Kafka, пересоздавать её и сбрасывать volume не нужно.

## Конфиг (`config/topics.yaml`)

```yaml
topics:
    orders:
        partitions: 3
        config:
            retention.ms: 172800000
```

### Параметры конфигурации топика

| Ключ                     | По умолчанию    | Что делает                                                       |
| ------------------------ | --------------- | ---------------------------------------------------------------- |
| `retention.ms`           | 7 дней          | сколько хранить сообщения (-1 — вечно)                           |
| `retention.bytes`        | -1 (без лимита) | лимит размера на партицию, удаление по размеру                   |
| `segment.ms`             | 7 дней          | через сколько секция лога закрывается и «откатывается» на новую  |
| `segment.bytes`          | 1 ГиБ           | то же по размеру секции                                          |
| `cleanup.policy`         | delete          | delete — удалять по сроку; compact — по ключу                    |
| `max.message.bytes`      | ~1 МБ           | максимальный размер сообщения                                    |
| `min.insync.replicas`    | 1               | сколько реплик должны подтвердить запись                         |
| `compression.type`       | producer        | как хранить сообщения (gzip, lz4, zstd и т.д.)                   |
| `message.timestamp.type` | CreateTime      | время создания (CreateTime) или записи на брокер (LogAppendTime) |

## Что делает

| Ситуация                           | Действие                                                           |
| ---------------------------------- | ------------------------------------------------------------------ |
| топика нет                         | создаёт (партиции, config, `REPLICATION_FACTOR`)                   |
| партиций в файле больше            | увеличивает                                                        |
| партиций в файле меньше            | **ошибка** (Kafka не умеет уменьшать), остальное применяет, exit 1 |
| значение в `config` отличается     | обновляет (`incremental_alter_configs`, трогает только свои ключи) |
| ключ убрали из `config`            | сбрасывает на значение по умолчанию                                |
| топик есть в Kafka, но нет в файле | не трогает (ничего не удаляет)                                     |

Повторный запуск безопасен: если всё уже совпадает, пишет «без изменений».

## Переменные окружения

| Переменная                | По умолчанию          | Что это                                                     |
| ------------------------- | --------------------- | ----------------------------------------------------------- |
| `KAFKA_BOOTSTRAP_SERVERS` | `localhost:9092`      | адрес Kafka                                                 |
| `TOPICS_CONFIG`           | `/config/topics.yaml` | путь к файлу с топиками                                     |
| `REPLICATION_FACTOR`      | `1`                   | фактор репликации для **новых** топиков                     |
| `RECONCILE_INTERVAL`      | `0`                   | `0` — применить и выйти; `N` — перечитывать файл каждые N с |

## Запуск

```bash
docker build -t kafka-admin .
docker run --rm -v "$PWD/config:/config:ro" \
  -e KAFKA_BOOTSTRAP_SERVERS=kafka:9092 \
  --network <сеть-с-kafka> kafka-admin
```

Режимы:

- **Один раз** (`RECONCILE_INTERVAL=0`, по умолчанию): правите `topics.yaml`, запускаете заново (`docker compose up -d kafka-admin`). Код возврата 1 — что-то не применилось.
- **Постоянно** (`RECONCILE_INTERVAL=10`): сервис сам подхватывает правки файла. Монтируйте **каталог** `config/`, а не один файл — иначе часть редакторов ломает монтирование.
